## 4. 关键问题

### 4.1 回退后，被移除的消息还会进入下一轮提示词吗？

分两层，证据充分度不同：

- **提示词历史来源唯一**：`U2.N(...)` 用 `c4.f4961n` 组装历史（`L1/U2.java:949-961`），只保留 `USER`/`ASSISTANT`（过滤器 `I1/C0258a.java:163-168`），message id 形如 `chat:<msgId>:<versionId>`（`U2.java:959`）。**没有第二份“隐藏消息”存储**。
- **删除是真实删除**：`L1/Y0.java:133-152` 直接把 id 从 `f4961n` 过滤掉并落盘，提示 `"消息已删除"`/`"已删除 N 条消息"`。因此删除后不会进入提示词。
- **重新生成**走 `drop(index+1)` 后再 `t0`（`L1/C0525d1.java:80-110`），被删消息不进提示词。
- **回退**：确认文案明说“删除其后的对话分支”（`M1/r.java:188`），但处理器方法体未反编译 → **回退的删除实现未验证**。可验证的是：只要消息离开 `f4961n`，就一定不发送（唯一来源）。
- 反向证据（会被误读）：`requestSnapshots`（`f4987w`）里仍保留旧 messages（见 4.2），但它们只用于 UI 展示，`N()` 不读该字段 → **旧快照不会重发**。

### 4.2 requestSnapshots 会被发送吗？

不会。`J1.C0396g0`（`CloudRequestSnapshot`）由 `L1/e3.java:245` 构造，字段顺序见 `J1/C0391e0.java:18-32`（id/createdAt/modelId/sourceIds/messages/estimatedInputTokens/inputBudgetTokens/configuredInputBudgetTokens/modelContextWindowTokens/outputReserveTokens/omittedHistoryMessages/actualPrompt/actualCompletion/promptCacheHit/promptCacheMiss/promptText）。写入 UI 状态时 `p015d2.n.P0(30, …)` **只保留最近 30 条**（`L1/K0.java:479`、`:560`），并由 `J5.w` 只读展示（`M1/J5.java:12022-12076`）。

### 4.3 “提示词回看”显示什么、何时记录？

- 入口：`"提示词预览"`（`C0785u.java:206`）、`"本轮发送清单"`（`:147`）、`"预览本轮实际发送清单"`（`C0777t.java:286`）、`"预览本轮提示词"`（`M1/r.java:124`）。
- 内容：顶部进度条 `估算/预算`（`J5.java:12037-12038`、`M1/D2.java:60-66`：`"输入 X / Y"`、`"输出 ≤ N"`、`"未纳入较早对话 N 条"`），下面按顺序给出**本轮将发送的全部 messages**，按 id 前缀分组：`chat:` → `"聊天记录 N 条"`（可收起，`C0739o0.java:489-492`）、`character:` → `"人物卡库"`（`M1/F2.java:100-103`）、其余逐条（`J5.java:12050-12069`）。
- 记录时机：`k0()` 预览时构造（`U2.java:7728-7755`，requestId = `"preview-"+UUID`）；真实发送时由 `e3.a` 在构造 prompt 的同一处生成并追加（`L1/K0.java:473`、`L1/U2.java:984`）。

### 4.4 Android 的预算公式与默认值（逐行）

设置读取/clamp（`I1/C0349t2.java:92-96`）：
- 输入预算 `input_budget_tokens` = `clamp(stored, 1024, 1_000_000)`
- 输出上限 `output_budget_tokens` = `clamp(stored, 1024, 100_000)`；`StoredSettings` 默认 **30000**（`I1/C0307j3.java:190`；旧默认 4096 有一次性迁移，`I1/C0338q2.java:41-46`）

有效输出预留 `p068s2.a.R0(reserve, ctxWindow, maxTokens)`（`p068s2/a.java:1328-1354`）：
```
i  = clamp(reserve,1024,100000)
if maxTokens > 0: i = min(i, maxTokens)
if ctx <= 0: return i
i4 = max(ctx-2048, 1024); iMin = (ctx-1024) - min(4096, i4)
return min(i, max(iMin,1024))
```
提示词预算 `L1/e3.a(...)`（`L1/e3.java:33-55`）：
```
out = clamp(outputReserve,1024,100000); 若 maxTokens>0 取 min
safe = ctx - (out + 1024)            // 1024 安全余量
若 safe < 1024 → throw "模型上下文窗不足以同时预留输出和安全空间；没有发送请求。"
inputBudget = min(configuredInputBudget, safe)
```
固定提示词超限（`e3.java:113-130`）：`"固定提示词与本轮指令估算约 N token，超过预算 M；请关闭或精简来源：…。没有发送请求。"`
历史裁剪（`e3.java:172-198`）：按“用户轮”从**末尾**整轮加入，累计 `iD + Σ` 不超过 `inputBudget`；被丢弃条数记入 `omittedHistoryMessages`（`e3.java:245`）。

## 5. 底部模式条语义：阅读 / 编辑 / 译文

- 三个标签来自 `M1/C0718l3.java:139-141`：`阅读` / `编辑` / `译文`，同一条的按钮在 `:150`：`返回阅读` / `编辑正文` / `编辑译文`；`:158`/`:187` 是 `上一步`/`下一步`（图标分别是 Undo 与 AutoMirrored.Filled.Redo，`:158`、`:168` —— 即**撤销/重做**，不是版本翻页）。
- 这些 case（2/3/4/5）的**唯一构造点全部在 `J5.i0`（阅读 Tab 的 ReaderScreen）内部**：smali `out/apktool/smali/M1/J5.smali:43247`（case 2）、`:43679`（case 3）、`:44051`（case 4）、`:44179`（case 5），均位于 `.method public static final i0(...)`（`J5.smali:39759`）。jadx 里 `J5.i0` 方法体缺失（`M1/J5.java:9671-9677`），所以 Java 侧看不到这些构造点。
- 结论：**它是阅读页内部的模式切换（同一页面内的状态切换），不是写作台的底栏，也不是独立页面**；`编辑正文/编辑译文` 进入该页的编辑态（`返回阅读` 退出），编辑态下才有 `上一步/下一步`（撤销/重做）。
- 阅读页是 `ManuscriptReaderSheet` 式的“页内编辑”还是“全屏覆盖”：**未验证**（方法体缺失）。
- 反证（说明它不属于写作台）：写作台底栏 `J5.java:2118` 传入的是 `C0718l3(…, 0)`（case 0，提交图标），不是 case 2/3/4/5。`M1/C7.java:468`（译文面板，`"暂无译文"` `:263`）用的是 case 7（图标按钮）。`J5.java:7753`（查找替换栏）用 case 1（两个输入框）。

## 6. 与 spec 的矛盾（`docs/spec/01-architecture.md`）

1. **§1.4 “创作 Tab 输入栏由 `C0718l3` 负责 阅读/编辑/译文” —— 错**。`J5.java:2118` 构造的是 case 0（提交图标）；三态模式条只在 `J5.i0`（阅读 Tab）内构造（§5 的 smali 证据）。

5. **§5.2 “正文分页/不完整护栏”** 与写作台无直接关系：写作台注入的正文片段是 `c3`（正文缓存）按 `f4925a0/f4931c0/f4934d0` 计算的尾部（`L1/U2.java:898-945`）。
