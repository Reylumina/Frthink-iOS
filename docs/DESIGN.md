# DESIGN.md · 视觉、交互与文案设计

`ARCHITECTURE.md` 说明技术架构，本页规定界面长什么样、怎么动、写什么字。改界面前先读本页，改完按第 9 节逐条检查。

- **基线**：设计和 SwiftUI 写法以 iOS 26.2 为准，CI 用 Xcode 26.3 + `iPhoneSimulator26.2.sdk` 构建。最低运行版本 iOS 17.0。两档的差别只在材质和少数系统控件（§5.2），层级、间距、字体、触控和文案规则两档一致。
- **依据**：Apple HIG 与 iOS 26 的 Liquid Glass 设计。本页没写到的情况，按 HIG 和系统控件的默认行为处理，不自己发明。
- **数值来源**：颜色、字体、间距、圆角、动效都从 `Core/Design/Theme.swift` 取。本页规定的 token 还没实现的，按本页命名补进 `Theme`；页面里不写颜色、字号和时长字面量。
- **机械检查**：`.swiftlint.yml` 和 `script/design_check.py` 只能查写死的数值；观感、层级和留白靠第 9 节加截图目检。

## 0. 原则与审美方向

Frthink 应该看起来像 iOS 自带的写作应用：安静、现代、正文占满注意力。具体来说：

1. **正文是第一层。** 任何页面，用户半秒内看到的应该是正文或本页唯一要做的事（§7.2）。导航和工具退到边缘，浮在内容之上。
2. **系统优先。** 能用系统控件、系统样式就不自己画。自绘组件需要写清系统缺了什么（写在组件注释里），并且只补缺的部分。
3. **两层结构。** 内容层是平的：纯色表面，不加玻璃，不加投影。控件层浮在上面：标签栏、工具栏、输入条、浮层，用系统玻璃或材质。两层之间只保留这两层。
4. **层级不靠颜色。** 把所有填充色去掉，层级仍要靠字号、字重、留白和位置成立。成立不了就重做布局；色块只用于状态和内容身份。
5. **只写必要的字。** 标题、数值、状态和原版有出处的句子可以写，解释性小字不写（§8）。

“现代”在这里指：浮起的玻璃控件、平的内容表面、同心圆角、系统字体排版、比例数字。下面这些是过时信号，出现即说明这一版不合格：

- 等宽字形做装饰，例如把“3 分钟前 · 187 字”整行设成等宽字体；
- 卡片同时加描边和投影；
- 每一行前面都放一个淡色方块图标；
- 满宽的灰色工具条压在内容上；
- 装饰性渐变、光晕、纹理和插画。

## 1. 颜色与材质

### 1.1 语义色

只用语义色，全局只有一个 tint：`Color.accentColor` 读资产目录的 `AccentColor`，值是单色（浅色近黑 #111111 / 深色近白 #F2F2F7）。内容型 App 的通行做法是把彩色让给内容：控件统一黑/白，颜色只出现在状态色和用户素材上；iOS 26 的玻璃本身是中性材质，再叠一个饱和色会打架。不引入自定义色相（墨绿、墨青这类低明度色不在考虑范围）。新增颜色一律先改资产目录，不在代码里写色值。

| 用途 | token | 说明 |
|---|---|---|
| 内容页底（写作台、阅读、正文编辑器） | `Theme.pageBackgroundColor` = `.systemBackground` | 浅色白，深色黑 |
| 表单页底（设置、世界资料、语料、提示词、导入导出） | `Theme.groupedPageColor` = `.systemGroupedBackground` | 与 iOS 设置相同 |
| 表单卡片 | `Theme.groupedCard` = `.secondarySystemGroupedBackground` | 由 `Form` / `List` 自动给出，不手画 |
| 内容页上的表面（卡片、用户气泡以外的容器） | `Theme.card` = `.secondarySystemBackground` | |
| 输入框、可点的次级容器 | `Theme.field` = `.tertiarySystemFill` | 比卡片深一档，用来区分可点和只读 |
| 选中态底 | `Theme.accentSoft` = `accent` 压 16% | 前景用 tint；圆钮、图标印章共用 |
| 强调色上的字形 | `Theme.onAccent`（资产 `OnAccent`，浅色白 / 深色近黑） | 发送键图标、码字机圆标 |
| 文字 | `.primary`、`.secondary`、`.tertiary` | `.tertiary` 只用于占位符和不可用状态 |
| 分隔线 | `.separator` | 一般由 `List` 给出 |

### 1.2 状态色

状态只用 `AppTone`，不直接写 `.green`、`.red`：

| tone | 颜色 | 用在 |
|---|---|---|
| `.neutral` | `.secondary` | 普通状态、计数 |
| `.accent` | tint | 当前项、进行中 |
| `.success` | 系统绿 | 已保存、连接成功 |
| `.warning` | 系统橙 | 缺 Key、接近上限、可恢复的失败 |
| `.danger` | 系统红 | 破坏性动作、不可恢复的失败 |

状态色只染图标、胶囊和少量文字，不染整块背景。破坏性按钮用 `role: .destructive`，让系统决定颜色。

### 1.3 透明度

- 文字颜色不能用 `opacity` 调深浅，要用 `.secondary`、`.tertiary`。透明度调出来的颜色不会响应“增强对比度”。
- 有色淡底（胶囊、选中态、图标底）统一用 `tint.opacity(Theme.tintedFillOpacity)`（16%），全项目只有这一个透明度。
- 用户气泡是唯一的实底例外：`Theme.bubbleFill`（系统灰 `.systemGray5`，浅色下浅灰、深色下深灰）填充、`Theme.bubbleForeground`（`.label`）文字，不加描边和投影。收发关系由实底/无底表达，和系统「信息」一致；助手回复不铺底色，直接是正文。强调色只留给可点控件：整块气泡铺强调色会把「一屏一个主操作」压掉，所以气泡不走强调色。
- 全局 tint 用语义色或单色；渐变与光晕只出现在进度条、图表这类数据表达里。

### 1.4 书封占位色

书封用 `Theme.Identity` 的 12 种纸色（朱红/橙/琥珀/橄榄/绿/青/湖蓝/靛/紫/玫/赭/石墨），按书项目 id 稳定取色，每种给出浅色与深色两档。这是全项目**唯一允许写死 hex 的地方**：它是内容身份色，不是语义色——系统动态色在白底上偏灰，一排书封看着像褪了色；手调色相才能让 12 本书一眼分开。除这里以外的任何颜色都必须来自语义色或资产目录。它是内容身份，不是品牌色，不用于按钮、开关、状态或页面底。占位封面上放四种书本轮廓之一（`book`/`book.closed`/`book.pages`/`books.vertical`），按 id 稳定取；不用带字、带文字行或非书类的图形（箱子、文件夹、报纸都不算书）（`book.pages`、`book.closed`、`books.vertical`、`text.book.closed`、`character.book.closed`、`doc.text`、`doc.plaintext`、`scroll`、`quote.opening`、`bookmark`），按同一个 id 稳定取，单色、同一字重、白色。不用书名首字。不加描边和装饰线。

**一级分类图标**用系统语义亮色 + 同一种形状：实底圆角方块 + 白色符号，每个分类固定一个色相（连接=蓝、提示词=紫、存档=青、存储=橙、外观=粉、关于=绿）。注意纸色（`Theme.Identity`）只给书封用——它是内容身份，低饱和；UI 图标要用系统色，否则整屏发闷。一级分类与系统设置同一个尺度（28pt、圆角 22.6%、字形 54%）。AI 服务商图标与系统图标同尺寸（32pt），用品牌标，不套圆角色块。

### 1.5 层级

全应用只有三层：

| 层 | 是什么 | 怎么做 |
|---|---|---|
| 0 页面 | 页面底色 | §1.1 的页底 token |
| 1 内容表面 | 卡片、气泡、列表分组、输入框 | 纯色填充 + 连续圆角；**不加投影，不加描边** |
| 2 浮起控件 | 标签栏、工具栏、底部输入条、菜单、浮层、sheet | iOS 26 用系统玻璃，17–25 用系统材质；投影由系统给 |

规则：

- 内容表面靠填充色和底色的差来分层。浅色下 `.secondarySystemBackground` 放在白底上已经能看出边界，不需要再加描边或投影。
- 卡片里不放卡片。表面里的分组用分隔线或留白。
- 第 2 层的投影、高光和模糊都交给系统，不手写 `.shadow`。唯一的手写投影例外是拖动中的元素。
- 开启“增强对比度”时，内容表面可以加 `.separator` 描边，这是唯一允许描边的情况。

`cardSurface(radius:)` 只做填充和圆角，描边与投影由系统材质提供；`Theme.cardShadow` 已移除。

### 1.6 玻璃

HIG 的规定是内容层不用 Liquid Glass，玻璃只给导航和控件层。

| 元素 | iOS 26 | iOS 17–25 |
|---|---|---|
| 标签栏、导航栏、工具栏 | 系统默认（自动是玻璃），不设自定义背景 | 系统默认 |
| 工具栏按钮 | 系统默认的玻璃分组；相关按钮放在同一组，组间用 `ToolbarSpacer(.fixed)` | 系统默认 |
| 底部输入条 | 续写、输入、发送同在一个玻璃胶囊里（一块表面），发送键是 34pt 强调色实心圆；不铺满宽底条 | `.bar` 材质满宽底条 + 内层实底胶囊 |
| sheet、菜单、popover | 系统默认，不设 `presentationBackground` | 系统默认 |
| 浮层按钮（如回到底部） | `.buttonStyle(.glass)` | `.regularMaterial` 圆形底 |
| 内容：气泡、卡片、正文 | 不用玻璃 | 不用材质 |

- 玻璃一律走 `glassSurface(radius:)`，它在 17–25 回落到 `.regularMaterial`。
- 相邻的多个玻璃元素放进同一个 `GlassEffectContainer`，单个不用。
- 主操作的玻璃按钮用 `.buttonStyle(.glassProminent)`，一屏最多一个，和 §5.4 的按钮分层一致。输入条的发送键例外：玻璃主操作会把它撑到 59pt（44pt 热区加玻璃内边距），比输入框还高，所以那一处用 34pt 实心圆（§5.9）。
- 滚动内容在浮起控件下方经过时，控件可读性由 `scrollEdgeEffectStyle(.soft, for:)` 保证。

## 2. 字体、排版与图标

### 2.1 字体角色

所有界面文字用 `Font.TextStyle`，跟随 Dynamic Type，最小 `.caption`（默认 12pt），不用 `.caption2`。中英文都用系统字体（SF、PingFang），不用自定义字体，也不用衬线字体——这是电子屏，不是纸：中文衬线在屏上笔画过细、字重不稳。层级靠字号、字重和留白，不靠换字体。

| 角色 | 样式 | token |
|---|---|---|
| 页面大标题 | 系统 `navigationTitle`，一级页用大标题 | — |
| 页内标题、卡片标题 | `.title3.weight(.semibold)` | `Theme.heading` |
| 区块标题 | 系统 `Section` 标题样式，只去掉大写变换 | `AppSectionHeader` |
| 行标题、按钮、界面正文 | `.body` | `Theme.label` |
| 行尾的值 | `.body`，`.secondary` 色 | `Theme.label` |
| 行内第二行、辅助信息 | `.subheadline`，`.secondary` 色 | `Theme.labelSmall` |
| 元信息（时间、字数、条数） | `.footnote`，`.secondary` 色 | `Theme.metadata`（新值） |
| 胶囊、角标 | `.caption.weight(.semibold)` | `Theme.badge` |
| 作品正文、码字机回复 | 正文字号基数（§2.3） | `ReaderStyle.bodyFont(size:)` |
| 用户消息 | `.body` | — |

**数字**：会变化的数字（计数、字数、时间、进度）用 `.monospacedDigit()`，保留系统字形，只让数字等宽，避免刷新时跳动。等宽字体（`design: .monospaced`）只用于本身就是代码的内容：API Key 片段、模型 id、JSON、错误码。`Theme.numeric` 和 `Theme.numericSmall` 改为比例字形加 `.monospacedDigit()`。

**数字和单位**：阿拉伯数字和中文单位之间留一个空格，例如 `187 字`、`2 张`、`3 分钟前`。用 `formatted()` 输出千分位。

### 2.2 字重

只用 `.regular`、`.medium`、`.semibold`。`.bold` 只给大标题（系统自动），不用 `.light` 和 `.heavy`。强调用字重或颜色，二选一，不叠加。

### 2.3 中文长文排版

正文是产品的核心，它的排版规则单独规定，覆盖阅读页、正文编辑器、码字机回复、流式文本和设置里的预览。

| 项 | 规则 |
|---|---|
| 字号基数 | 外观设置的 `bodyFontSize`，默认 18pt，范围 13–28；经 `UIFontMetrics` 跟随 Dynamic Type，见 `Core/Design/DynamicTypeFont.swift` |
| 阅读页字号 | 阅读设置单独可调，换算方式同上 |
| 行高 | 默认 1.5 倍，换算统一走 `ReaderStyle.lineSpacing(size:lineHeight:)`；阅读页可调 1.2–2.0，其他正文场景固定 1.5 |
| 段落 | 按原文换行分段，空行只当分隔符，不占行高。段距全项目只有一个值：`Theme.Layout.paragraphSpacing`（12pt），阅读页、完成态气泡、流式气泡共用，不按字号缩放、不叠加。不自动加首行缩进 |
| 行宽 | 每行不超过 36 个汉字。正文栏最大宽度 = 字号 × 36，超出时居中，两侧留白（§5.3） |
| 对齐 | 左对齐。SwiftUI `Text` 不支持两端对齐，需要时只能包 UIKit 并设 `NSParagraphStyle.alignment = .justified`，目前不做 |
| 颜色 | `.primary`。阅读页的黑底模式不跟随系统深浅色，前景用 `ReaderStyle.ink(dark:)` |
| 选中、搜索高亮 | `ReaderStyle.highlightColor(current:)`，当前命中比其他命中深一档 |
| 正文外的元素 | 页脚进度、章节名用 `.footnote`、`.secondary`，不和正文抢层级。页脚另有一条 `Theme.Layout.progressBarHeight`（2pt）的进度条，进度色用 tint |

流式气泡、正文编辑器、阅读页和设置预览共用同一套字号和行高换算，任何一处单独改数值都算违规。

### 2.4 图标

- 只用 SF Symbols。AI 服务商用各自的品牌标（见 README），品牌标不拉伸、不改色。
- 图标尺寸靠 `.font` 或 `.imageScale` 控制，跟随相邻文字，不用 `.frame` 定尺寸。确实需要固定的控件尺寸时用 `@ScaledMetric`。
- 字重跟随相邻文字，不单独指定。
- 默认单色渲染。状态图标可以用 `.symbolRenderingMode(.hierarchical)`。实心变体（`.fill`）只表示「选中 / 当前」或本身就是实心语义的符号（`lock.fill`、`xmark.circle.fill`、`checkmark.circle.fill` 这类），不拿实心做装饰；标签栏由系统处理。
- 有色方块图标（`IconTile`）只出现在**一级分类列表**（设置首页、世界概览）：基准 28pt（`Theme.Layout.iconTileSize`，全应用唯一取值）、圆角 22.6%、字形占 54%、medium 字重，尺寸走 `@ScaledMetric`；`ProviderIcon` 用同一基准并同样缩放。
- 二级、三级页不放图标：行里只有标题和值（`SettingsLabelRow`）。动作行（重新计算、导入导出、从正文提炼）也不配图标——标题已经说明动作，符号只会让人猜它和资源行的区别。颜色取系统动态色（`.blue`、`.indigo`、`.orange`、`.purple`、`.pink`、`.teal`、`.gray`），同一类资料固定一个色相；没有专属含义的行用中性灰。AI 服务商图标用品牌标，不套方块。
- 只有图标的按钮必须设 `accessibilityLabel`。
- 符号动效（`symbolEffect`）只表达状态，例如生成中用 `.pulse`，不做装饰。

## 3. 间距、圆角与形状

### 3.1 间距

```
间距  4 · 8 · 12 · 16 · 24 · 32
token xs · s · m · l · xl · xxl   （Theme.Spacing）
```

不用 5、7、10、14。用途约定：

| 间距 | 用在 |
|---|---|
| 4 | 图标和紧挨的文字、同一字段内的标题和计数 |
| 8 | 行内元素之间、标签和输入框之间 |
| 12 | 列表行里图标和标题之间、卡片内边距（紧凑） |
| 16 | 页面水平边距、卡片内边距、字段之间 |
| 24 | 区块之间 |
| 32 | 页面顶部和底部的大留白、空态上下 |

`List` 和 `Form` 的内部间距由系统决定，不覆盖。

### 3.2 圆角

```
圆角  8 · 12 · 16 · 24      （Theme.Radius：small · medium · large · sheet）
```

| 圆角 | 用在 |
|---|---|
| 8 | 胶囊以外的小标签、缩略图 |
| 12 | 输入框、书封 |
| 16 | 卡片、气泡 |
| 24 | 自绘的弹层 |
| 胶囊 | 状态胶囊、玻璃按钮、输入条 |

一律用 `.continuous` 圆角。

### 3.3 同心

iOS 26 的形状跟随容器：嵌在别的圆角容器里的形状，圆角要和外层同心，不能用固定值硬套。

- iOS 26：嵌套在 sheet、卡片或玻璃容器里的自绘形状用 `ConcentricRectangle`，或 `.rect(corners: .concentric(minimum:))`，最小值取 §3.2 的对应档。
- iOS 17–25：回落到 §3.2 的固定值。
- 两档的切换统一封装在 `Theme` 里（新增 `Theme.containerShape(minimum:)`），页面里不写 `#available` 分支。
- 内外圆角的估算关系：内圆角 = 外圆角 − 内边距。算出来小于 8 时取 8。

## 4. 动效与反馈

### 4.1 动效

只用系统弹簧预设，每个动画都要对应一个状态变化：选中、展开、可发送、生成中、出现和消失。不做装饰性动画。

| token | 预设 | 用在 |
|---|---|---|
| `Theme.motionSelection` | `.snappy(duration: 0.2)` | 选中、开关、分段切换、聚焦描边 |
| `Theme.motionLayout`（新增） | `.smooth` | 展开收起、搜索栏出现、toast 进出、列表插入删除 |
| `Theme.motionEmphasis`（新增） | `.bouncy` | 直接操作的结果，例如消息发出、插入正文成功；一屏同时最多一个 |

- 不用 `.easeInOut`、`.easeOut`、`.linear` 和自定义时长。
- 页面跳转、sheet 弹出、标签切换都用系统转场，不自定义。
- 流式文本逐字出现时不加动画，只有插入完成时用一次 `motionEmphasis`。
- “减弱动态效果”开启时，位移和缩放改为淡入淡出，`motionEmphasis` 退化为 `motionLayout`（§5.6）。

### 4.2 触感

只用 `.sensoryFeedback`，并且全部受设置项 `hapticsEnabled` 控制。

| 时机 | 反馈 |
|---|---|
| 分段、选项切换 | `.selection` |
| 开始生成、发送消息 | `.impact(weight: .light)` |
| 插入或追加正文成功、保存成功 | `.success` |
| 生成失败、连接失败 | `.error` |
| 破坏性操作确认后 | `.warning` |

不在滚动、逐字流式输出、每次按键时触发触感。同一个动作只触发一次。

### 4.3 提示与撤销

- 操作结果用 toast 提示，一次只显示一条，用 `motionLayout` 进出，自动消失。toast 只写结果（例如「已插入正文」），不写说明。
- 可撤销的操作在 toast 里放「撤销」，不再弹确认。
- 不可撤销的操作先确认（§5.8），确认后不再弹 toast。

## 5. 布局与交互

### 5.1 通用布局

标签和值两端对齐，不用空格凑：

```swift
HStack {
    Text(title)
    Spacer(minLength: Theme.Spacing.s)
    Text(value).foregroundStyle(.secondary).monospacedDigit()
}
```

- 不给文字写死 `.frame(width:height:)`，Dynamic Type 放大时会裁字。图标、封面、控件可以有固定尺寸，但要用 `@ScaledMetric`。
- 可点目标的热区至少 44×44pt。图标按钮看起来可以小，热区用 `.frame(minWidth: 44, minHeight: 44)` 加 `.contentShape(Rectangle())` 扩大，不能只放大图标。
- 同一行里的控件可见高度统一成 `Theme.Layout.controlHeight`（36pt）：搜索框、次要操作胶囊、圆形图标按钮。圆形按钮按 36pt 画圆，外面再包一层 44pt 的透明框，所以行高是 44、视觉是 36，三者对齐。
- 列表行不设 44pt 的**内容**最小高度：行高 = 行内容 + 系统内边距。iOS 26 的系统内边距是 22–30pt，行内容写成 44 会让行高变成 66–74pt，设置页六行就多占一屏。列表行内容一律用 `Theme.Layout.rowContentHeight`（28pt）——包括只读数值行、开关行、章节行、语料行；44pt 是行总高，由系统内边距补足（28pt），实测（1206×2622 模拟器截图）从 198px/行收到 143px/行，即 66pt → 47.7pt，整行可点，热区够。行内边距仍交给系统（§3.1）。
- `controlHeight`、`inlineControl` 这些控件尺寸是基准值，视图里用 `@ScaledMetric(relativeTo: .body)` 读，随字号一起放大（§2.4）。
- 状态行只占一行：图标在文字前，动作在行尾。图标不能单独占一行。
- `TextEditor` 不放进外层 `ScrollView`。

### 5.2 iOS 26 与 17–25

两档在下面这些地方不同，其他规则一致。分支统一封装在 `Theme` 或共用组件里，页面代码不写 `#available`。

| 项 | iOS 26 | iOS 17–25 |
|---|---|---|
| 材质 | Liquid Glass（§1.6） | 系统材质 |
| 标签栏 | 浮起玻璃。创作和阅读页用 `.tabBarMinimizeBehavior(.onScrollDown)`，滚动时收起 | 系统默认 |
| sheet 工具栏 | 关闭用 `Button(role: .close)`，确认用 `Button(role: .confirm)`，系统画 × 和 ✓ | 文字按钮「取消」「完成」/「保存」 |
| 页面工具栏 | 按钮自动成组为玻璃，用 `ToolbarSpacer` 分组 | 系统默认 |
| 滚动边缘 | `scrollEdgeEffectStyle(.soft, for:)` | 系统默认 |
| 嵌套圆角 | 同心（§3.3） | 固定值 |

### 5.3 宽度适配

应用同时支持 iPhone 和 iPad（`TARGETED_DEVICE_FAMILY = 1,2`）。iPhone 只支持竖屏，iPad 支持四个方向，并且 iPadOS 的窗口可以随意调整大小。所以布局只按**可用宽度**判断，不按设备型号判断。

| 宽度 | 判断 | 规则 |
|---|---|---|
| 紧凑 | `horizontalSizeClass == .compact` | 本页其余规则的默认情况 |
| 常规 | `horizontalSizeClass == .regular` | 内容不随窗口拉伸，见下表 |

常规宽度下各类页面的最大宽度：

| 页面 | 最大宽度 | token |
|---|---|---|
| 正文（阅读、编辑器、码字机回复） | 字号 × 36 | 由 `ReaderStyle` 计算（新增） |
| 对话列（创作页整列） | 720pt | `Theme.Layout.chatMaxWidth`（新增） |
| 表单（设置、世界资料、编辑器） | 640pt | `Theme.Layout.formMaxWidth`（新增） |
| 用户气泡 | 所在列宽的 80% | — |

- 超出最大宽度时内容居中，两侧露出页面底色。用 `.frame(maxWidth:)` 或 `.contentMargins` 实现，不写死宽度。
- 不为 iPad 单独做侧边栏或分栏布局。保留标签栏，iPadOS 怎么呈现由系统决定。
- 检查尺寸：iPhone SE（375pt 宽）、标准 iPhone（393pt）、Pro Max（440pt）、iPad 竖屏全屏，以及 iPad 窄窗口。

### 5.4 按钮

| 层 | 样式 | 数量 |
|---|---|---|
| 主操作 | `PrimaryActionButton`（`.borderedProminent`）；浮在内容上时用 `.glassProminent` | 一屏最多一个 |
| 输入条发送键 | 34pt 强调色实心圆（`Theme.Layout.inlineControl`），不用玻璃主操作 | 一屏一个 |
| 次操作 | `SecondaryActionButton`（`.bordered`）；浮在内容上时用 `.glass` | 不限，并排不超过两个 |
| 行内动作 | 纯文字按钮，`.borderless` | 不限 |
| 空态动作 | `EmptyStateView` 默认 `.bordered`；整屏再没有别的入口时才用实底（目前只有书架首启） | 一屏一个 |
| 破坏性 | `DestructiveActionRow`，放在页面最后一个独立 Section | 一页一个 |
| 工具栏 | 系统默认，只放图标或短词 | 一侧不超过 3 个 |

### 5.5 Dynamic Type

- 从 `.xSmall` 到 `.accessibility5` 都不能裁字，不能重叠。
- 进入无障碍字号（`dynamicTypeSize.isAccessibilitySize`）后，标签加值的横排行改为竖排：标题在上，值在下。可以用 `ViewThatFits` 自动切换。
- 行数可以增加，`lineLimit` 只用于标题和元信息这类允许截断的文字，正文和错误原文不截断。
- 固定尺寸的控件用 `@ScaledMetric` 跟随缩放。

### 5.6 深色模式与无障碍

- 深色模式只靠语义色自动适配，不写 `colorScheme == .dark` 分支。阅读页的黑底模式是用户设置，不算例外。
- **减弱动态效果**：读 `accessibilityReduceMotion`，按 §4.1 降级。
- **降低透明度**：材质一律用系统玻璃或系统材质，它们会自动变成不透明；这个设置才能真正生效。
- **增强对比度**：语义色自动加深；内容表面按 §1.5 加描边。
- **粗体文本**：字重交给 `Font.TextStyle`，这个设置才能自动生效。
- **VoiceOver**：
  - 只有图标的按钮要写 `accessibilityLabel`。
  - 一行里的标题、值和状态用 `.accessibilityElement(children: .combine)` 合成一个元素。
  - 装饰图标设 `accessibilityHidden(true)`。
  - 流式生成过程中不逐字播报，只在开始和结束时各播报一次。
  - 滑动操作（删除、恢复）同时提供 `accessibilityActions`。
- 对比度：文字和背景至少 4.5:1。`.tertiary` 只用于占位符和不可用状态，不用来显示需要读的信息。

### 5.7 状态

每个异步页面都要覆盖下面五种状态，并且使用同一套组件：

| 状态 | 怎么显示 | 组件 |
|---|---|---|
| 加载中 | 先显示加载态；确认结果为空之前不显示空态 | `ProgressView` 或骨架占位 |
| 空 | 整页用 `EmptyStateView`（`ContentUnavailableView` 风格），区块内用 `InlineEmptyState`；文字只用标题或原版有出处的句子（§8.3） | 同左 |
| 错误 | 区块内用 `AppStatusLine(.failure)`，显示服务端原文，最多 3 行；可以重试时在行尾放「重试」 | `AppStatusLine` |
| 生成中 | 发送按钮变成停止按钮；流式文本直接显示，不加占位动画 | — |
| 不可用 | 控件 `.disabled`，由系统变灰；行尾不再另写说明 | — |

`AppStatusLine` 自带最小高度，状态在“无”和“一行”之间切换时页面不会跳动。

### 5.8 保存与确认

- 自动保存的页面只显示「完成」（iOS 26 为 ✓），不显示自动保存角标。
- 显式保存的页面用「取消」放弃、「保存」提交（iOS 26 为 × 和 ✓），保存按钮不兼做切换当前项。
- 只有「保存」没有「取消」的编辑页，左滑返回时自动保存非空改动；带草稿的 sheet 关闭前要确认放弃，不能静默丢掉输入。
- 正文编辑的撤销、重做用系统机制：`UndoManager` 注册改动，工具栏不放常驻的「撤销/重做」按钮。iPad 键盘走 ⌘Z / ⇧⌘Z，iPhone 走系统的摇一摇、三指轻扫和编辑菜单。插入正文这类应用级动作也注册进同一套 `UndoManager`，撤销提示用 toast（§4.3），不再单独画一条工具条。
- 清除 Key、清零用量、恢复默认、删除分组、删除词条、删除书稿都要确认。能撤销的操作优先提供撤销（§4.3），不弹确认。
- 确认用 `confirmationDialog`，只有标题和动作按钮，没有解释性 message。
- 滑块只在松手时保存，不在每次拖动时写入整份 `settings.json`。
- 发送或续写后收起键盘，流式文本进入对话区。插入和追加正文都有确认和撤销。

### 5.9 键盘与输入条

- 不加自定义的「完成」键盘工具条。
- 滚动区用 `.scrollDismissesKeyboard(.interactively)`。
- 底部输入条放在 `.safeAreaInset(edge: .bottom)` 里，键盘避让交给系统。输入条的材质见 §1.6。
- 流式刷新按 33ms 一帧（约 30 帧/秒）：60ms 时一次补三四个字，观感是一跳一跳；低电量与过热时自动降频到 80–100ms。
- 流式生成期间也按同一套规则排版：`StreamingTextView` 逐段算字号、段内按 `**` 切 run 换字重，标题完成态与流式用同一组缩放（1.45 / 1.26 / 1.12），换气泡时高度不跳；新增文字里出现 `#` 或 `**` 时整段重排，避免按后缀排错。
- 码字机回复支持基本 Markdown：行内加粗/斜体走 `AttributedString(markdown:)`，块级只认一到三级标题（行首 `# `、`## `、`### `），字号按正文派生 1.45 / 1.26 / 1.12 倍、字重 semibold；不解析列表、分隔线，避免把小说正文里的星号和短横线误读成结构。
- 思考过程默认收起，只有一行文字（「思考过程（N 字）」），点一下展开、再点收起；不用 `DisclosureGroup`，它自带的箭头图标在触屏上是多余的。
- 气泡的操作收进长按菜单（`contextMenu`），不在气泡下面挂常驻图标条：每条回复重复一排按钮既占高度又抢层级。用户气泡的菜单里有「撤回」（删掉该指令及其之后的消息，带一次撤销），助手气泡有复制/插入/追加/重新生成/回退/清理版本/删除/多选。
- 键盘弹起时，正文区右上角浮一个圆形 X（`ToolbarCircleIcon`）：点一下收起键盘；滚动收起由 `.scrollDismissesKeyboard(.interactively)` 负责。
- 顶栏（玻璃上的图标）用系统裸符号，不套方块、不套描边圆——那一层交给系统玻璃；正文区的动作图标用 `IconTile`。
- 续写、输入框、发送/停止三件控件包在**同一个胶囊表面**里，不各自成块：左侧续写、中间输入、右侧发送，同一条中轴，热区都是 44pt。发送键是 34pt 强调色实心圆，其余可见高度 `Theme.Layout.inlineControl`（34pt）。整条只出现一个玻璃/实底表面，外层不再套第二个胶囊。
- 输入框随行数长高（最多 5 行）；多行时两侧按钮保持居中。

### 5.10 页面级别

| 级别 | 例子 | 要求 |
|---|---|---|
| 一级 | 5 个标签页 | 一屏做一件事，不嵌套工具栏 |
| 二级 | 设置分类页、世界页分段、阅读页 | 一页不超过 4 个区块，一屏一个主操作 |
| 三级 | 人物卡、事件卡、世界书、语料、供应方、世界建立 | 字段标题在输入框上方，字段间距 16，删除放在最后一节并二次确认 |
| 四级 | 编辑器里的 sheet、确认弹窗 | 只做一个决定；长文编辑不用 sheet；有未保存改动时关闭前确认 |

共用组件在 `Core/Design/AppComponents.swift` 和 `Theme.swift`。二级、三级页面优先用 `Form` / `List` 加下面的组件，不手写分隔线区块，不在卡片里套卡片。

| 组件 | 用途 |
|---|---|

| `StatusPill` | 当前、已停用、未填 Key 等状态胶囊 |

| `CircleIconLabel`、`CircleIconButton` | 行内圆钮：可见 36pt、热区 44pt；`Menu` 用前者当 label |
| `AppStatusLine` | 一行业务状态：进行中、成功、失败、普通 |
| `AppTextField`、`AppSecureField` | 单行字段，标题在上 |
| `AppTextArea`、`AppTextEditor` | 多行字段、长正文编辑 |

## 6. 信息架构

设置分三级：

| 级 | 放什么 | 硬约束 |
|---|---|---|
| 一级 | 分类列表：连接与模型、写作、数据、外观与交互、关于 | 一屏看完，不超过 6 行 |
| 二级 | 该分类的功能页 | 一页不超过 4 个区块 |
| 三级 | 编辑器或弹层：供应方、技能、语料库、世界建立、存档 | 只做一件事 |

缺 Key 这类全局提醒只在一级留一条可以点进去的入口，不铺成卡片。

书架在 sheet 里分三段：继续写作、全部书稿、回收站和设置入口。不铺大封面网格，书脊、书名和最近编辑时间就是索引，书脊占位色只用于封面。回收站是 push 出来的独立页面，行内只留「恢复」，彻底删除走滑动操作加确认。

世界页分为概览、世界书、人物卡、事件卡、模板与规则。概览只放刷新入口和资料计数，没有单独的「世界设定」编辑器，旧的设定文本迁移成世界书词条。点击资料计数行切换到对应分栏，不写实现说明。

阅读页正文优先，常驻控件不超过 4 个，其余放进菜单。

## 7. 体验依据

方法参考内置的 [ios-taste 技能](skills/ios-taste/SKILL.md)（vendored，MIT，见 [NOTICE](skills/ios-taste/NOTICE.md)）；改界面以本页规则为准。

### 7.1 用户与场景

用户是写中文长篇小说的作者，常在手机上用整块时间写作，一本书可能超过 50 万字。

打开应用时，用户通常想接着上次的段落写，或者先让码字机写一段再改。环境一般比较安静，常常单手拿手机，另一只手用来选字或粘贴。

用户需要在 10 秒内完成三件事：确认正文写到哪里，输入或生成下一段，把它插入正文并确认位置。

界面的情绪目标是平静、专注、可信。层次来自系统材质、字号、字重、留白和精细的间距；正文始终是第一层，导航和操作退后。

### 7.2 半秒测试

| 页面 | 不看字，用户先看到什么 |
|---|---|
| 创作 | 一整列对话，底部一个输入框。正文入口在导航栏，不和对话抢空间 |
| 阅读 | 一页小说：正文和页脚进度。目录、搜索、设置在导航栏 |
| 世界 | 概览里的刷新入口和资料计数，世界书、人物、事件、规则各一栏 |
| 设置 | 系统分组列表，点分类进入 |

创作页优先显示对话，因为这一页的主要操作是说清本轮的写作要求。正文是对话的上下文，点击正文进入全屏页面阅读或编辑。

## 8. 文案规则

### 8.1 可以写

| 类型 | 例子 |
|---|---|
| 标题 | 页面标题、区块名、字段名、按钮名 |
| 数值、计数、状态 | `2 张`、`4 分钟前`、`未填写`、`当前`、`已缓存` |
| 服务端或错误原文 | 测试连接失败时服务端返回的正文，导入失败的具体键名 |
| 结果提示 | toast 里的结果，例如「已插入正文」 |
| 极短占位 | 输入框 placeholder，例如「书名」「人物本名」 |
| 原版有证据的空态句 | 见 §8.3 |
| 法定署名 | `Power by Fr33`、移植声明、版本行 |

### 8.2 不写

- 区块副标题和 footer 里的解释，比如「写作、整理和翻译默认都走……」。
- 行副标题，比如「全局预设、技能、本书补充指令」。
- 操作说明，比如「点行尾的 ⋯ 可以……」「左滑可……」。
- 实现或行为解释，比如「Key 只存本机钥匙串」「模型留空时使用……」「主写作固定 0.2」。
- `InlineHint`、`settingsNote` 和自动保存小字（比如 `AutosaveBadge`）。
- 确认弹窗里的解释性 message，只留标题和动作按钮。
- 空态里自己编的引导句，只留原版有证据的句子或标题。

### 8.3 原版有证据、可以保留

| 页面 | 原文 | 证据 |

### 8.4 写法

- 按钮用动词或动宾短语：「保存」「插入正文」「重试」，不用「确定」「好的」。
- 标题和按钮不加句号。toast 和空态句按原文。
- 数字和中文单位之间空一格（§2.1）。
- 界面文案里引用界面元素时用「」。

## 9. 评审清单
