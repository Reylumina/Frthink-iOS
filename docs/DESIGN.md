# DESIGN.md · 视觉、交互与文案设计

`ARCHITECTURE.md` 说明技术架构，本页规范界面的视觉呈现、动效行为与文本规范。修改界面前请先查阅本页，完成后按第 9 节逐项核对。

- **基线**：设计和 SwiftUI 写法以 iOS 26.2 为准，CI 用 Xcode 26.3 + `iPhoneSimulator26.2.sdk` 构建。最低运行版本 iOS 17.0。两档的差别只在材质和少数系统控件（§5.2），层级、间距、字体、触控和文案规则两档一致。
- **依据**：遵循 Apple HIG 与 iOS 26 的 Liquid Glass 设计规范。本页未涵盖的场景，遵循 HIG 及系统控件的默认行为处理，不额外自创规则。
- **数值来源**：颜色、字体、间距、圆角与动效均取自 `Core/Design/Theme.swift`。若本页规定的 token 尚未实现，按本页命名规范补充至 `Theme`；页面代码中禁止硬编码颜色、字号与动画时长字面量。
- **自动化检查**：`.swiftlint.yml` 与 `script/design_check.py` 用于检测硬编码数值；整体观感、层级与留白则依照第 9 节结合截图进行人工目视审查。

## 0. 原则与审美方向

Frthink 的设计目标是贴近 iOS 原生写作应用质感：沉静、现代、凸显正文主体。具体原则如下：

1. **正文是第一层。** 任何页面，用户半秒内看到的应该是正文或本页唯一要做的事（§7.2）。导航和工具退到边缘，浮在内容之上。
2. **系统优先。** 优先使用系统控件与系统样式，避免自行绘制。对于自绘组件，需在代码注释中明确系统控件缺失的能力，且仅补充缺失部分。
3. **层次分明。** 内容区域（页面底 + 内容表面）保持平坦，不加玻璃、不加投影；导航与控件浮在内容之上（标签栏、工具栏、输入条、浮层），使用系统玻璃或材质（§1.5）。
4. **层级不靠颜色。** 即便移除全部填充色，界面层级仍需通过字号、字重、留白与布局建立；色块仅用于表达状态和内容标识。
5. **文本保持克制精炼。** 仅展示标题、数值、状态、结果提示及原版有出处的句子（§8）。

## 1. 颜色与材质

### 1.1 语义色

只使用语义色，全局仅保留单一 tint：`Color.accentColor` 读取资产目录的 `AccentColor`，取单色（浅色近黑 #111111 / 深色近白 #F2F2F7）。内容型应用应将色彩空间留给正文内容：控件统一采用中性黑白，色彩仅用于状态指示与用户素材，以契合 iOS 26 的中性玻璃质感。新增颜色一律先在资产目录中定义，禁止在代码中硬编码颜色字面量（由 lint 校验）。

| 用途 | token | 说明 |
|---|---|---|
| 内容页底（写作台、阅读、正文编辑器） | `Theme.pageBackgroundColor` = `.systemBackground` | 浅色白，深色黑 |
| 表单页底（设置、世界资料、语料、提示词、导入导出） | `Theme.groupedPageColor` = `.systemGroupedBackground` | 与 iOS 设置相同 |
| 表单卡片 | `Theme.groupedCard` = `.secondarySystemGroupedBackground` | 由 `Form` / `List` 自动提供，无需手动绘制 |
| 内容页上的表面（卡片、用户气泡以外的容器） | `Theme.card` = `.secondarySystemBackground` | |
| 输入框、可交互的次级容器 | `Theme.field` = `.tertiarySystemFill` | 比卡片背景加深一级，用于区分可交互与只读状态 |
| 选中态底色 | `Theme.accentSoft` = `accent` 叠加 16% 不透明度 | 前景使用 tint；圆形按钮与图标印章共用 |
| 强调色上的字形 | `Theme.onAccent`（资产 `OnAccent`，浅色白 / 深色近黑） | 发送键图标、码字机圆标 |
| 文字 | `.primary`、`.secondary`、`.tertiary` | `.tertiary` 只用于占位符和不可用状态 |
| 分隔线 | `.separator` | 一般由 `List` 给出 |

### 1.2 状态色

状态只用 `AppTone`，不直接写 `.green`、`.red`：

| tone | 颜色 | 用在 |
|---|---|---|
| `.neutral` | `.secondary` | 普通状态、计数 |
| `.accent` | tint | 当前项、进行中 |
| `.success` | 系统绿 | 已保存、连接成功 |
| `.warning` | 系统橙 | 缺 Key、接近上限、可恢复的失败 |
| `.danger` | 系统红 | 破坏性动作、不可恢复的失败 |

状态色只染图标、胶囊和少量文字，不染整块背景。破坏性按钮用 `role: .destructive`，让系统决定颜色。

### 1.3 透明度

- 文本颜色不得通过 `opacity` 调节明暗，应使用 `.secondary`、`.tertiary` 等语义色彩。通过透明度混合的颜色无法响应系统的“增强对比度”辅助功能。
- 有色淡底（胶囊、选中态、图标底）统一用 `tint.opacity(Theme.tintedFillOpacity)`（16%），全项目只有这一个透明度。
- 用户气泡是唯一的实底例外：`Theme.bubbleFill`（系统灰 `.systemGray5`，浅色下浅灰、深色下深灰）填充、`Theme.bubbleForeground`（`.label`）文字，不加描边和投影。收发关系由实底/无底表达，和系统「信息」一致；助手回复不铺底色，直接是正文。强调色只留给可点控件：气泡全幅使用强调色会削弱“一屏单一主操作”的视觉焦点，因此用户气泡不采用强调色。
- 全局 tint 用语义色或单色；渐变与光晕只出现在进度条、图表这类数据表达里。

### 1.4 书封占位色

这是全项目**唯一允许硬编码十六进制色值（hex）之处**：该颜色作为内容标识色而非语义色使用——系统动态色在浅色背景下偏灰，连续书封排列容易产生褪色感；通过专门调校的色相以确保 12 种书封具有明确的视觉区分度。除此处外，其余所有颜色均须取自语义色或资产目录。其定位为内容标识，非品牌色，禁止应用于按钮、开关、状态指示或页面底色。占位封面上展示四种书本轮廓之一（`book`/`book.closed`/`book.pages`/`books.vertical`），按标识稳定映射，采用单色、统一字重与纯白填充；禁止使用包含字符、文本行或非书本类图标（如箱子、文件夹、报纸等）。不采用书名首字，不添加描边及装饰线条。

**一级分类图标**用系统语义亮色 + 同一种形状：实底圆角方块 + 白色符号，每个分类固定一个色相（连接=蓝、提示词=紫、存档=青、存储=橙、外观=粉、关于=绿）。注意纸色（`Theme.Identity`）只给书封用——它是内容身份，低饱和；UI 图标与人物卡默认头像（44pt 实底圆 + 白色 `person.fill`）要用系统色，否则界面整体视觉偏暗沉。一级分类与系统设置同一个尺度（28pt、圆角 22.6%、字形 54%）。AI 服务商图标用同一基准（28pt、圆角 22.6%）并同样缩放，采用官方品牌 SVG。

### 1.5 层级

全应用只有三层：

| 层级 | 定义 | 实现方式 |
|---|---|---|
| 0 页面 | 页面底色 | §1.1 的页底 token |
| 1 内容表面 | 卡片、气泡、列表分组、输入框 | 纯色填充 + 连续圆角；**不加投影，不加描边** |
| 2 浮起控件 | 标签栏、工具栏、底部输入条、菜单、浮层、sheet | iOS 26 用系统玻璃，17–25 用系统材质；投影由系统给 |

规则：

- 内容表面靠填充色和底色的差来分层。浅色下 `.secondarySystemBackground` 放在白底上已经能看出边界，无需额外添加描边或投影。
- 避免在卡片中嵌套卡片。表面里的分组用分隔线或留白。
- 第 2 层的投影、高光和模糊都交给系统，仅在拖动交互中的元素上手动指定 `.shadow`。
- 开启“增强对比度”时，内容表面补充 `.separator` 描边。

`cardSurface(radius:)` 负责填充、圆角与增强对比度描边。

### 1.6 玻璃

遵循 HIG 规范，内容呈现层不采用 Liquid Glass 效果，玻璃材质仅应用于导航与悬浮控件层。

| 元素 | iOS 26 | iOS 17–25 |
|---|---|---|
| 标签栏、导航栏、工具栏 | 系统默认（自动是玻璃），不设自定义背景 | 系统默认 |
| 工具栏按钮 | 系统默认的玻璃分组；相关按钮放在同一组，组间用 `ToolbarSpacer(.fixed)` | 系统默认 |
| 底部输入条 | 续写、输入、发送同在一个玻璃胶囊里（一块表面），发送键是 34pt 强调色实心圆；不铺满宽底条 | `.bar` 材质满宽底条 + 内层实底胶囊 |
| sheet、菜单、popover | 系统默认，不设 `presentationBackground` | 系统默认 |
| 浮层按钮（如回到底部） | `.buttonStyle(.glass)` | `.regularMaterial` 圆形底 |
| 内容：气泡、卡片、正文 | 不用玻璃 | 不用材质 |

- 玻璃一律走 `glassSurface(radius:)`，它在 17–25 回落到 `.regularMaterial`。
- 相邻的多个玻璃材质元素应置于同一个 `GlassEffectContainer` 中管理，单个元素无需包裹。
- 主操作的玻璃按钮用 `.buttonStyle(.glassProminent)`，一屏最多一个，和 §5.4 的按钮分层一致。采用玻璃主操作样式会将控件扩展至 59pt（44pt 触控热区加上玻璃材质内边距），高度超过输入框，因此该处统一采用 34pt 实心圆设计（详见 §5.9）。
- 滚动内容在浮起控件下方经过时，控件可读性由 `scrollEdgeEffectStyle(.soft, for:)` 保证。

## 2. 字体、排版与图标

### 2.1 字体角色

所有界面文字用 `Font.TextStyle`，跟随 Dynamic Type，最小 `.caption`（默认 12pt），不用 `.caption2`。不采用自定义字体或衬线字体——在移动屏幕显示环境下，中文衬线字体笔画较细且字重渲染不稳定。视觉层级应依托字号、字重与留白构建，而非通过切换字体类型。

| 角色 | 样式 | token |
|---|---|---|
| 页面大标题 | 系统 `navigationTitle`，一级页用大标题 | — |
| 页内标题、卡片标题 | `.title3.weight(.semibold)` | `Theme.heading` |
| 区块标题 | 系统 `Section` 标题样式，只去掉大写变换 | `AppSectionHeader` |
| 行标题、按钮、界面正文 | `.body` | `Theme.label` |
| 行尾的值 | `.body`，`.secondary` 色 | `Theme.label` |
| 行内第二行、辅助信息 | `.subheadline`，`.secondary` 色 | `Theme.labelSmall` |
| 元信息（时间、字数、条数） | `.footnote`，`.secondary` 色 | `Theme.metadata` |
| 胶囊、角标 | `.caption.weight(.semibold)` | `Theme.badge` |
| 作品正文、码字机回复 | 正文字号基数（§2.3） | `ReaderStyle.bodyFont(size:)` |
| 用户消息 | `.body` 基数（17pt 随 Dynamic Type 缩放，经 `JustifiedText` 两端对齐） | `Theme.Typography.bodyBaseSize` |

**数字**：会变化的数字（计数、字数、时间、进度）用 `.monospacedDigit()`，保留比例字形并只让数字等宽，避免刷新时跳动；`Theme.numeric` 与 `Theme.numericSmall` 已封装此规则。等宽字体（`design: .monospaced`）只用于代码类内容（API Key 片段、模型 id、JSON、错误码）。

**数字和单位**：阿拉伯数字和中文单位之间留一个空格，例如 `187 字`、`2 张`、`3 分钟前`。用 `formatted()` 输出千分位。

### 2.2 字重

仅使用 `.regular`、`.medium` 与 `.semibold`。`.bold` 仅用于大标题（由系统自动应用），不使用 `.light` 与 `.heavy`。视觉强调应在字重或颜色中二选一，避免重叠使用。

### 2.3 中文长文排版

正文是产品的核心，它的排版规则单独规定，覆盖阅读页、正文编辑器、码字机回复、流式文本和设置里的预览。

| 项 | 规则 |
|---|---|
| 字号基数 | 外观设置的 `bodyFontSize`，默认 18pt，范围 13–28；经 `UIFontMetrics` 跟随 Dynamic Type，见 `Core/Design/DynamicTypeFont.swift` |
| 阅读页字号 | 阅读设置单独可调，换算方式同上 |
| 行高 | 默认 1.5 倍，换算统一走 `ReaderStyle.lineSpacing(size:lineHeight:)`；阅读页可调 1.2–2.0，其他正文场景固定 1.5 |
| 段落 | 根据原文换行符分段，空行仅作为分隔标记，不额外占用行高。项目统一采用如下段距换算公式：`Theme.Layout.paragraphSpacing(fontSize:lineHeight:)` = 额外行距 × 1.4，其中额外行距 = 字号 × (行高 − 1)。在默认行高 1.5 时，段距等于字号 × 0.7（例如 18pt 对应 12.6pt）。以额外行距为计算基准，当阅读页行距调整为 1.2 或 2.0 时，段距同步联动变化，使段间距与文本折行间距始终保持 1.4 倍比例。该规则由阅读页、创作页全文编辑器（`ManuscriptTextEditor`，将连续空行折叠为单一段落间距）、完成态气泡、用户气泡及流式气泡统一复用，不重复累加。不自动追加首行缩进 |
| 行宽 | 每行不超过 36 个汉字。正文栏最大宽度 = 字号 × 36，超出时居中，两侧留白（§5.3） |
| 对齐 | 两端对齐。SwiftUI `Text` 的 `multilineTextAlignment` 没有 justify、也不读 `NSParagraphStyle`，正文与气泡一律走 `Core/Design/JustifiedText.swift` 或 `ManuscriptTextEditor`（`UITextView` + TextKit + `WriterTypography`）：`alignment = .justified`、`lineBreakStrategy = .pushOut`、`hyphenationFactor = 0.85`，中文行首禁则由 CoreText 处理。用户气泡开启 `shrinksToFitWidth = true`，短句按实际宽度收缩、长句满宽两端对齐。流式输出过程中末段文本持续追加，排版暂保持 `.natural`，待段落生成完成后再执行两端对齐 |
| 颜色 | `.primary`，统一跟随系统深浅色外观 |
| 选中、搜索高亮 | `ReaderStyle.highlightColor(current:)`，当前命中比其他命中深一档 |
| 正文外的元素 | 页脚进度、章节名用 `.footnote`、`.secondary`，不和正文抢层级。页脚另有一条 `Theme.Layout.progressBarHeight`（2pt）的进度条，进度色用 tint |

流式气泡、正文编辑器、阅读页和设置预览共用同一套字号和行高换算，任何一处单独改数值都算违规。

### 2.4 图标

- 只用 SF Symbols。AI 服务商用各自的品牌标（见 README），品牌标不拉伸、不改色。
- 图标尺寸靠 `.font` 或 `.imageScale` 控制，跟随相邻文字，避免使用 `.frame` 硬编码尺寸。确实需要固定的控件尺寸时用 `@ScaledMetric`。
- 字重跟随相邻文字，不单独指定。
- 默认单色渲染。状态图标可以用 `.symbolRenderingMode(.hierarchical)`。实心变体（`.fill`）只表示「选中 / 当前」或本身就是实心语义的符号（`lock.fill`、`xmark.circle.fill`、`checkmark.circle.fill` 这类），不将实心样式作为纯装饰用途；标签栏由系统处理。
- 有色方块图标（`IconTile`）只出现在**一级分类列表**（设置首页、世界概览）：基准 28pt（`Theme.Layout.iconTileSize`，全应用唯一取值）、圆角 22.6%、字形占 54%、medium 字重，尺寸走 `@ScaledMetric`；`ProviderIcon` 用同一基准（28pt、圆角 22.6%，内边距 4%）并同样缩放。
- 二级、三级页不放图标：行里只有标题和值（`SettingsLabelRow`）。动作行（重新计算、导入导出、从正文提炼）也不配图标——标题已经说明动作，附加图标容易混淆动作项与资源项的语义界限。AI 服务商图标使用内置 17 套品牌 SVG（OpenAI 兼容按服务地址自动匹配厂商图标并回落 OpenAI）。
- 只有图标的按钮必须设 `accessibilityLabel`。
- 符号动效（`symbolEffect`）只表达状态，例如生成中用 `.pulse`，不做装饰。

## 3. 间距、圆角与形状

### 3.1 间距

```
间距  4 · 8 · 12 · 16 · 24 · 32
token xs · s · m · l · xl · xxl   （Theme.Spacing）
```

用途约定（禁用值由 lint 拦截）：

| 间距 | 用在 |
|---|---|
| 4 | 图标和紧挨的文字、同一字段内的标题和计数 |
| 8 | 行内元素之间、标签和输入框之间 |
| 12 | 列表行里图标和标题之间、卡片内边距（紧凑） |
| 16 | 页面水平边距、卡片内边距、字段之间 |
| 24 | 区块之间 |
| 32 | 页面顶部和底部的大留白、空态上下 |

`List` 和 `Form` 的内部间距由系统决定，不覆盖。

### 3.2 圆角

```
圆角  8 · 12 · 16 · 24      （Theme.Radius：small · medium · large · sheet）
```

| 圆角 | 用在 |
|---|---|
| 8 | 胶囊以外的小标签、缩略图 |
| 12 | 输入框、书封 |
| 16 | 卡片、气泡 |
| 24 | 自绘的弹层 |
| 胶囊 | 状态胶囊、玻璃按钮、输入条 |

一律用 `.continuous` 圆角。

### 3.3 同心

iOS 26 遵循容器嵌套形状自适应规则：内嵌于圆角容器中的图形，其圆角应与外层容器保持同心，避免套用固定数值。

- iOS 26：嵌套在 sheet、卡片或玻璃容器里的自绘形状用 `ConcentricRectangle`，或 `.rect(corners: .concentric(minimum:))`，最小值取 §3.2 的对应档。
- iOS 17–25：回落到 §3.2 的固定值。
- 两档的切换统一封装在 `Theme` 里（`Theme.containerShape(minimum:)`），页面里不写 `#available` 分支。
- 内外圆角的估算关系：内圆角 = 外圆角 − 内边距。算出来小于 8 时取 8。

## 4. 动效与反馈

### 4.1 动效

只用系统弹簧预设，每个动画都要对应一个状态变化：选中、展开、可发送、生成中、出现和消失。避免引入装饰性动画。

| token | 预设 | 用在 |
|---|---|---|
| `Theme.motionSelection` | `.snappy(duration: 0.2)` | 选中、开关、分段切换、聚焦描边 |
| `Theme.motionLayout` | `.smooth` | 展开收起、搜索栏出现、toast 进出、列表插入删除 |
| `Theme.motionEmphasis` | `.bouncy` | 直接操作的结果，例如消息发出、插入正文成功；一屏同时最多一个 |

- 不用 `.easeInOut`、`.easeOut`、`.linear` 和自定义时长。
- 页面跳转、sheet 弹出、标签切换都用系统转场，不自定义。
- 流式文本逐字出现时不加动画，只有插入完成时用一次 `motionEmphasis`。
- “减弱动态效果”开启时，位移和缩放改为淡入淡出，`motionEmphasis` 退化为 `motionLayout`（§5.6）。

### 4.2 触感

只用 `.sensoryFeedback`，并且全部受设置项 `hapticsEnabled` 控制。

| 时机 | 反馈 |
|---|---|
| 分段、选项切换 | `.selection` |
| 开始生成、发送消息 | `.impact(weight: .light)` |
| 插入或追加正文成功、保存成功 | `.success` |
| 生成失败、连接失败 | `.error` |
| 破坏性操作确认后 | `.warning` |

滚动过程中、逐字流式输出时及按键键入时不触发触觉反馈。单次操作仅触发一次反馈。

### 4.3 提示与撤销

- 操作结果用 toast 提示，一次只显示一条，用 `motionLayout` 进出，自动消失。Toast 仅提示操作结果（如「已插入正文」），不附带说明性冗余文本。
- 可撤销的操作在 toast 里放「撤销」，不再弹确认。
- 不可撤销的操作先确认（§5.8），确认后不再弹 toast。

## 5. 布局与交互

### 5.1 通用布局

标签与对应数值两端对齐，禁止使用空格填充对齐：

```swift
HStack {
    Text(title)
    Spacer(minLength: Theme.Spacing.s)
    Text(value).foregroundStyle(.secondary).monospacedDigit()
}
```

- 禁止为文本硬编码 `.frame(width:height:)`，以免在 Dynamic Type 放大时产生文本截断。图标、封面、控件可以有固定尺寸，但要用 `@ScaledMetric`。
- 可点目标的热区至少 44×44pt。图标按钮视觉尺寸可保持精致，但触控热区须通过 `.frame(minWidth: 44, minHeight: 44)` 与 `.contentShape(Rectangle())` 扩充，避免单纯放大图标本身。
- 同一行里的控件可见高度统一成 `Theme.Layout.controlHeight`（36pt）：搜索框、次要操作胶囊、圆形图标按钮。圆形按钮按 36pt 绘制圆角，外层包裹 44pt 透明响应区域，使触控行高达到 44pt 且视觉呈现为 36pt，确保与其他控件视觉对齐。
- 列表行不设 44pt 的**内容**最小高度：行高 = 行内容 + 系统内边距。iOS 26 的系统内边距为 22–30pt，若将列表行内容高度指定为 44pt，累加系统内边距后实际行高将达到 66–74pt，导致设置页仅展示数行即占满一屏。列表行内容一律使用 `Theme.Layout.rowContentHeight`（28pt）——包括只读数值行、开关行、章节行与语料行；44pt 为行总高，由系统内边距补足（28pt），实测（1206×2622 模拟器截图）行高从 198px 降至 143px（66pt → 47.7pt），整行可交互且触控热区充足。行内边距交由系统默认处理（详见 §3.1）。
- `controlHeight`、`inlineControl` 这些控件尺寸是基准值，视图里用 `@ScaledMetric(relativeTo: .body)` 读，随字号一起放大（§2.4）。
- 状态行只占一行：图标在文字前，动作在行尾。图标不能单独占一行。
- `TextEditor` 不放进外层 `ScrollView`。
- 测量尺寸统一用 `.onGeometryChange(for:transform:action:)` 返回轻量 `Equatable` 值，不用 `GeometryReader` 包裹测量。
- 删除确认与未保存放弃确认统一走 `AppFormComponents` 的 `deleteConfirmationDialog` / `discardChangesDialog`（内部封装居中 `.alert`），不在业务视图中重复手写弹窗。

### 5.2 iOS 26 与 17–25

两档在下面这些地方不同，其他规则一致。分支统一封装在 `Theme` 或共用组件里，页面代码不写 `#available`。

| 项 | iOS 26 | iOS 17–25 |
|---|---|---|
| 材质 | Liquid Glass（§1.6） | 系统材质 |
| 标签栏 | 浮起玻璃。创作和阅读页用 `.tabBarMinimizeBehavior(.onScrollDown)`，滚动时收起 | 系统默认 |
| sheet 工具栏 | 关闭用 `Button(role: .close)`（仅取系统 × 外观；有未保存修改时先拦截确认放弃），确认用 `Button(role: .confirm)`，系统画 × 和 ✓ | 文字按钮「取消」「完成」/「保存」 |
| 页面工具栏 | 按钮自动成组为玻璃，用 `ToolbarSpacer` 分组 | 系统默认 |
| 滚动边缘 | `scrollEdgeEffectStyle(.soft, for:)` | 系统默认 |
| 嵌套圆角 | 同心（§3.3） | 固定值 |

### 5.3 宽度适配

应用同时支持 iPhone 和 iPad（`TARGETED_DEVICE_FAMILY = 1,2`）。iPhone 只支持竖屏，iPad 支持四个方向，并且 iPadOS 的窗口可以随意调整大小。所以布局只按**可用宽度**判断，不按设备型号判断。

| 宽度 | 判断 | 规则 |
|---|---|---|
| 紧凑 | `horizontalSizeClass == .compact` | 本页其余规则的默认情况 |
| 常规 | `horizontalSizeClass == .regular` | 内容不随窗口拉伸，见下表 |

常规宽度下各类页面的最大宽度：

| 页面 | 最大宽度 | token |
|---|---|---|
| 正文（阅读、编辑器、码字机回复） | 字号 × 36 | 由 `ReaderStyle` 计算 |
| 对话列（创作页整列） | 720pt | `Theme.Layout.chatMaxWidth` |
| 表单（设置、世界资料、编辑器） | 640pt | `Theme.Layout.formMaxWidth` |
| 用户气泡 | 所在列宽的 80% | — |

- 超出最大宽度时内容居中，两侧露出页面底色。用 `.frame(maxWidth:)` 或 `.contentMargins` 实现，不写死宽度。
- 不为 iPad 单独做侧边栏或分栏布局。保留标签栏，iPadOS 怎么呈现由系统决定。
- 检查尺寸：iPhone SE（375pt 宽）、标准 iPhone（393pt）、Pro Max（440pt）、iPad 竖屏全屏，以及 iPad 窄窗口。

### 5.4 按钮

| 层 | 样式 | 数量 |
|---|---|---|
| 主操作 | `PrimaryActionButton`（`.borderedProminent`）；浮在内容上时用 `.glassProminent` | 一屏最多一个 |
| 输入条发送键 | 34pt 强调色实心圆（`Theme.Layout.inlineControl`），不用玻璃主操作 | 一屏一个 |
| 次操作 | `SecondaryActionButton`（`.bordered`）；浮在内容上时用 `.glass` | 不限，并排不超过两个 |
| 行内动作 | 纯文字按钮，`.borderless` | 不限 |
| 空态动作 | `EmptyStateView` 默认 `.bordered`；整屏再没有别的入口时才用实底（目前只有书架首启） | 一屏一个 |
| 破坏性 | `DestructiveActionRow`，放在页面最后一个独立 Section | 一页一个 |
| 工具栏 | 系统默认，只放图标或短词 | 一侧不超过 3 个 |

### 5.5 Dynamic Type

- 从 `.xSmall` 到 `.accessibility5` 都不能裁字，不能重叠。
- 进入无障碍字号（`dynamicTypeSize.isAccessibilitySize`）后，标签加值的横排行改为竖排：标题在上，值在下。可以用 `ViewThatFits` 自动切换。
- 行数可以增加，`lineLimit` 只用于标题和元信息这类允许截断的文字，正文和错误原文不截断。
- 固定尺寸的控件用 `@ScaledMetric` 跟随缩放。

### 5.6 深色模式与无障碍

- 深色模式全部由语义色与系统材质自动适配，页面代码中不写 `colorScheme == .dark` 分支。
- **减弱动态效果**：读 `accessibilityReduceMotion`，按 §4.1 降级。
- **降低透明度**：材质一律用系统玻璃或系统材质，它们会自动变成不透明；这个设置才能真正生效。
- **增强对比度**：语义色自动加深；内容表面按 §1.5 加描边。
- **粗体文本**：字重交给 `Font.TextStyle`，这个设置才能自动生效。
- **VoiceOver**：
  - 只有图标的按钮要写 `accessibilityLabel`。
  - 一行里的标题、值和状态用 `.accessibilityElement(children: .combine)` 合成一个元素。
  - 装饰图标设 `accessibilityHidden(true)`。
  - 流式生成过程中不逐字播报，只在开始和结束时各播报一次。
  - 滑动操作（删除、恢复）同时提供 `accessibilityActions`。
- 对比度：文字和背景至少 4.5:1。`.tertiary` 只用于占位符和不可用状态，不用来显示需要读的信息。

### 5.7 状态

每个异步页面都要覆盖下面五种状态，并且使用同一套组件：

| 状态 | 怎么显示 | 组件 |
|---|---|---|
| 加载中 | 先显示加载态；确认结果为空之前不显示空态 | `ProgressView` 或骨架占位 |
| 空 | 整页用 `EmptyStateView`（`ContentUnavailableView` 风格），区块内用 `InlineEmptyState`；文字只用标题或原版有出处的句子（§8.3） | 同左 |
| 错误 | 区块内用 `AppStatusLine(.failure)`，显示服务端原文，最多 3 行；可以重试时在行尾放「重试」 | `AppStatusLine` |
| 生成中 | 发送按钮变成停止按钮；流式文本直接显示，不加占位动画 | — |
| 不可用 | 控件 `.disabled`，由系统变灰；行尾不再另写说明 | — |

`AppStatusLine` 自带最小高度，状态在“无”和“一行”之间切换时页面不会跳动。

### 5.8 保存与确认

- 自动保存的页面只显示「完成」（iOS 26 为 ✓），不显示自动保存角标。
- 显式保存的页面用「取消」放弃、「保存」提交（iOS 26 为 × 和 ✓），保存按钮不兼做切换当前项。
- 仅提供「保存」而无「取消」选项的编辑页面，左滑返回时自动持久化非空修改；包含未保存草稿的浮层（sheet）在关闭前须提示放弃修改确认，避免静默丢失输入内容。
- 正文编辑的撤销与重做采用系统原生机制：通过 `UndoManager` 注册变更，工具栏不常驻「撤销/重做」按钮。iPad 外接键盘支持 ⌘Z 与 ⇧⌘Z，iPhone 支持系统摇一摇、三指轻扫及编辑菜单。插入正文等应用级动作亦统一注册至 `UndoManager`，撤销提示通过 Toast 呈现（详见 §4.3），避免单独绘制额外的操作工具条。
- 清除 Key、清零用量、恢复默认、删除分组、删除词条、删除书稿都要确认。能撤销的操作优先提供撤销（§4.3），不弹确认。
- 用户主动发起的破坏性或放弃修改确认，以及非预期的系统错误/关键阻断提示，统一使用居中 `.alert`（仅标题、必要正文与动作按钮，确认操作用 `role: .destructive`），不使用从底部弹出的 `confirmationDialog`。
- 滑动选择器仅在释放触控时触发保存，避免在拖动过程中高频写入 `settings.json`。
- 发送或续写后收起键盘，流式文本进入对话区。插入和追加正文都有确认和撤销。

### 5.8.1 文件选择

- `.fileImporter`／`.fileExporter` 挂在**页面层**，不挂在触发的按钮或 List 行上：列表行存在复用机制，且在面板收起的同时于同一视图立即弹出新页面会被系统丢弃，导致交互无响应。
- 从菜单或动作表触发的选择器，延迟一个运行循环（约 350ms）后再更新状态，避免与菜单收起动画产生同一帧渲染冲突。
- 选择器只负责拿到 URL，读取放在后台任务里，安全作用域访问在同一个任务内成对 begin/end。

### 5.9 键盘与输入条

- 滚动区用 `.scrollDismissesKeyboard(.interactively)`。
- 底部输入条放在 `.safeAreaInset(edge: .bottom)` 里，键盘避让交给系统（自定义键盘工具条由 lint 禁用）。输入条的材质见 §1.6。
- 流式渲染刷新率控制为 33ms 一帧（约 30 帧/秒）：若设置为 60ms，单次渲染追加多个字符容易产生顿挫感；在低电量或设备发热场景下，自动降频至 80–100ms。
- 流式生成期间也按同一套规则排版：`StreamingTextView` 与完成态气泡共用 `WriterTypography`，按已完成段落维护前缀偏移，每帧仅对新增完成段落与末尾进行中段落执行 `O(末段)` 增量 `NSTextStorage.replaceCharacters` 更新，换气泡时高度不跳。
- 码字机回复与用户气泡支持基本 Markdown：行内加粗/斜体统一走 `MarkdownInline.runs(_:)` 与 `WriterTypography.attributedDocument`（流式与完成态同一份解析，标记本身不显示；用户气泡配 `JustifiedText(..., shrinksToFitWidth: true)`），块级只认一到三级标题（行首 `# `、`## `、`### `），字号按正文派生 1.45 / 1.26 / 1.12 倍、字重 semibold；不解析列表、分隔线，避免把小说正文里的星号和短横线误读成结构。
- 思考过程默认折叠，仅保留单行文本摘要（如「思考过程（N 字）」），点击可展开或再次折叠；不使用 `DisclosureGroup`，以避免系统默认箭头图标带来的多余视觉干扰。
- 气泡相关操作统一收拢至长按菜单（`NoPreviewContextMenu`，基于 UIKit `UIContextMenuInteraction` + 空 `visiblePath`），不在气泡下方常驻图标条，亦不显示气泡标题头与预览缩略图卡片。用户气泡菜单提供「撤回」（删除该指令及后续消息，将该指令回填至输入框，并支持撤销恢复原草稿），助手气泡提供复制/插入/追加/提取为人物卡/重新生成/回退/清理版本/删除；多选属于独立模式，统一由顶栏的“更多（⋯）”菜单进入。
- 键盘弹出时，正文区域右上角悬浮展示圆形关闭按钮（`ToolbarCircleIcon`）：点击即可收起键盘；交互式滚动收起则由 `.scrollDismissesKeyboard(.interactively)` 处理。
- 顶栏（悬浮于玻璃材质上的图标）采用系统原生符号，无需添加背景方块或描边圆环——该层级视觉效果依托系统玻璃材质呈现；正文区域的操作图标则统一使用 `IconTile`。
- 续写、输入框、发送/停止三件控件放在底部输入条同一中轴上：左侧续写（34pt 圆形玻璃按钮）、中间输入（玻璃/实底胶囊）、右侧发送（34pt 强调色实心圆），热区均补到 44pt。
- 输入框高度随文本行数动态自适应（最多 5 行）；多行显示时两侧控制按钮保持垂直居中。

### 5.10 页面级别

| 级别 | 例子 | 要求 |
|---|---|---|
| 一级 | 5 个标签页 | 一屏做一件事，不嵌套工具栏 |
| 二级 | 设置分类页、世界页分段、阅读页 | 一页不超过 4 个区块，一屏一个主操作 |
| 三级 | 人物卡、事件卡、世界书、语料、供应方、世界建立 | 字段标题在输入框上方，字段间距 16，删除放在最后一节并二次确认 |
| 四级 | 编辑器里的 sheet、确认弹窗 | 只做一个决定；长文编辑不用 sheet；有未保存改动时关闭前确认 |

共用组件在 `Core/Design/AppComponents.swift`、`Core/Design/AppFormComponents.swift` 和 `Theme.swift`。二级、三级页面优先用 `Form` / `List` 加下面的组件，不手写分隔线区块，不在卡片里套卡片。

| 组件 | 用途 |
|---|---|

| `CircleIconLabel`、`CircleIconButton` | 行内圆钮：可见 36pt、热区 44pt；`Menu` 用前者当 label |

| `AppTextArea`、`AppTextEditor` | 多行字段、长正文编辑 |
| `PrimaryActionButton`、`SecondaryActionButton`、`DestructiveActionRow` | 按钮三层（§5.4） |

## 6. 信息架构

设置分三级：

| 级 | 放什么 | 硬约束 |
|---|---|---|
| 一级 | 分类列表：连接与模型、写作、数据、外观与交互、关于 | 单屏呈现完整内容，不超过 6 行 |
| 二级 | 该分类的功能页 | 一页不超过 4 个区块 |
| 三级 | 编辑器或弹层：供应方、技能、语料库、世界建立、存档 | 只做一件事 |

缺少 API Key 等全局提示仅在第一级保留可点击进入的入口行，避免铺展为大面积卡片。

书架在 sheet 里分三段：继续写作、全部书稿、回收站和设置入口，使用分组列表呈现书脊、书名和最近编辑时间。回收站是 push 出来的独立页面，行内只留「恢复」，彻底删除走滑动操作加确认。

世界页分为概览、世界书、人物卡、事件卡、模板与规则。概览只放资料计数，点击资料计数行切换到对应分栏；刷新人物卡入口只在人物分栏出现一次。

阅读页正文优先，常驻控件不超过 4 个，其余放进菜单。

## 7. 体验依据

方法参考内置的 [ios-taste 技能](skills/ios-taste/SKILL.md)（vendored，MIT，见 [NOTICE](skills/ios-taste/NOTICE.md)）；改界面以本页规则为准。

### 7.1 用户与场景

用户是写中文长篇小说的作者，常在手机上用整块时间写作，一本书可能超过 50 万字。

启动应用时，用户的典型诉求是承接既有段落继续创作，或借助码字机自动生成后续内容后再行润色。使用环境通常较为安静，常见单手握持设备、另一手进行文字选择或粘贴的操作模式。

用户需要在 10 秒内完成三件事：确认正文写到哪里，输入或生成下一段，把它插入正文并确认位置。

界面的情绪目标是平静、专注、可信。层次来自系统材质、字号、字重、留白和精细的间距；正文始终是第一层，导航和操作退后。

### 7.2 半秒测试

| 页面 | 未浏览具体文字时，用户的视觉落点 |
|---|---|
| 创作 | 一整列对话，底部一个输入框。正文入口在导航栏，不和对话抢空间 |
| 阅读 | 一页小说：正文和页脚进度。目录、搜索、设置在导航栏 |
| 世界 | 概览里的资料计数，世界书、人物、事件、规则各一栏；刷新入口只在人物栏 |
| 设置 | 系统分组列表，点分类进入 |

创作页优先显示对话，因为该页面的核心操作在于明确本轮生成的写作诉求。正文是对话的上下文，点击正文进入全屏页面阅读或编辑。

## 8. 文案规则

### 8.1 可以写

| 类型 | 例子 |
|---|---|
| 标题 | 页面标题、区块名、字段名、按钮名 |
| 数值、计数、状态 | `2 张`、`4 分钟前`、`未填写`、`当前`、`已缓存` |
| 服务端或错误原文 | 测试连接失败时服务端返回的正文，导入失败的具体键名 |
| 结果提示 | toast 里的结果，例如「已插入正文」 |
| 极短占位 | 输入框 placeholder，例如「书名」「人物本名」 |
| 原版有确切出处的空态文案 | 见 §8.3 |
| 法定署名 | `Power by Fr33`、移植声明、版本行 |

### 8.2 精简约束

只保留 §8.1 列出的必要信息；以下几类说明性文案一律省略（已删除的 `InlineHint`、`AutosaveBadge`、`settingsNote` 由 lint 拦截）：

- 区块副标题、行副标题及 footer 解释文案；
- 操作引导与实现/行为说明（如「左滑可…」「只存本机钥匙串」）；
- 确认弹窗的解释性 message（只留标题和动作按钮）；
- 自拟的空态引导句（仅保留 §8.3 有出处的原文）。

### 8.3 原版有确切依据可保留的文案

| 页面 | 原文 | 证据 |
|---|---|---|
| 世界书空态 | 「当前项目尚无世界书」和「添加设定后，只保存在这本书中。」 | `M1/C0722m.java:366` |
| 宇宙头部 | 「全局预设、共享世界书与 Skill」 | `M1/C0738o.java:312-313` |
| 世界页头部 | 「世界」和「这本书的设定与人物」 | `M1/C0738o.java:167-168` |
| 书架标题 | 「书架」 | 用户 2026-11-12 指定；原版为「本机书架」，移植版不再沿用 |
| 回收站状态 | 「项目已在回收站」「项目已恢复到书架」「项目已从书架隐藏」 | `dex-chinese.txt:1940,1941,143` |
| 阅读页空态 | 「暂无正文」「暂无译文」（配 `globe` 图标） | 用户指定精简文案 |
| 创作页输入框占位 | 「告诉码字机你的创作想法…」 | 用户指定文案 |

空态句、头部副标题这类说明性句子，在字符串表或规格里查不到出处的，视为自拟文案，删除。§8.1 列出的标题、数值、状态和结果提示不需要出处。

### 8.4 写法

- 按钮用动词或动宾短语：「保存」「插入正文」「重试」，不用「确定」「好的」。
- 标题和按钮不加句号。toast 和空态句按原文。
- 数字和中文单位之间空一格（§2.1）。
- 界面文案里引用界面元素时用「」。
